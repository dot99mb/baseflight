# Подключение внешних устройств

Ниже `TX` и `RX` названы со стороны полётного контроллера. Для любого внешнего
устройства нужна общая земля с контроллером. Контакт питания выбирайте по
схеме конкретной платы: исходники не позволяют достоверно указать, где на
разъёме находятся 3,3 В и 5 В.

## 1. Радиоприёмник

### PPM/CPPM

| Приёмник | Контроллер |
|---|---|
| PPM signal | PA0 / RC1 / PWM1 |
| GND | GND платы |
| VCC | питание, требуемое приёмником и поддерживаемое платой |

Нужно включить `FEATURE_PPM`. Этот режим освобождает RC2..RC8 для некоторых
других функций и является обязательным условием инициализации сонара в текущем
`main.c`.

### Параллельный PWM, NAZE

Подключите сигналы каналов 1..8 соответственно к PA0, PA1, PA2, PA3, PA6,
PA7, PB0, PB1. Если включён GPS, PA2/PA3 переходят в USART2 и два входных
канала пропускаются. Если выбран SerialRX, параллельный захват входов полностью
отключается.

### Параллельный PWM, CJMCU

Шесть входов в карте CJMCU: PA0, PA1, PA2, PA3, PA8, PA11. Они соответствуют
RC1..RC6 в порядке перечисления.

### SBUS

| Приёмник | NAZE |
|---|---|
| SBUS OUT | PA3 / USART2_RX |
| GND | GND |
| питание | по требованиям приёмника и платы |

Драйвер включает аппаратный инвертор через PB2, принимает 100000 бод, 8E2.
Следовательно, ожидается вход платы, связанный с предусмотренным инвертором.
Не следует одновременно добавлять внешний инвертор, не проверив конкретную
схему клона.

### SUMD и IBUS

| Приёмник | Контроллер |
|---|---|
| Serial OUT | PA3 / USART2_RX |
| GND | GND |

Оба драйвера используют 115200 бод, 8N1 и только RX контроллера. PB2-инвертор
для них не включается.

### Spektrum satellite

Обычный вариант:

| Satellite | Контроллер |
|---|---|
| DATA | PA3 / USART2_RX |
| GND | GND |
| VCC | только напряжение, допустимое для конкретного satellite |

На NAZE-SP можно задать `spektrum_sat_on_flexport=1`; тогда DATA подключается
к PB11 / USART3_RX. Для bind-последовательности прошивка временно переключает
эту же RX-линию в open-drain output и выдаёт число импульсов из
`spektrum_sat_bind` (1..10). В compile-time варианте `HARDWARE_BIND_PLUG`
добавляется активный низкий вход PB5.

## 2. GPS

Основное подключение NAZE:

| GPS | Контроллер |
|---|---|
| GPS TX | PA3 / USART2_RX |
| GPS RX | PA2 / USART2_TX |
| GND | GND |
| VCC | по схеме модуля и платы |

Для NMEA прошивка включает только RX, поэтому GPS RX/PA2 не обязателен. Для
UBLOX/MTK нужен двунаправленный UART, чтобы прошивка могла конфигурировать
модуль. USART2 делится с SerialRX.

Если одновременно используются SerialRX и SoftSerial, GPS переводится на
SoftSerial 1:

| GPS | NAZE SoftSerial 1 |
|---|---|
| GPS TX | PA6 / SoftSerial1 RX |
| GPS RX | PA7 / SoftSerial1 TX |

В этом сочетании скорость GPS ограничивается максимумом SoftSerial; код снижает
её до 38400 бод при необходимости. Однако CLI текущей версии допускает для
`softserial_baudrate` максимум 19200, что следует учитывать при ручной настройке.

Исключение: если Spektrum уже вынесен на FlexPort (`PB11`), GPS остаётся на
USART2.

## 3. ESC, сервоприводы и коллекторные моторы

### NAZE, типичный квадрокоптер

Для параллельного PWM или PPM без сервоприводов первые четыре сигнальных выхода:

| Устройство | GPIO | Логический порт |
|---|---|---|
| ESC/Motor 1 signal | PA8 | PWM9 |
| ESC/Motor 2 signal | PA11 | PWM10 |
| ESC/Motor 3 signal | PB6 | PWM11 |
| ESC/Motor 4 signal | PB7 | PWM12 |
| ESC/Motor 5 signal | PB8 | PWM13 |
| ESC/Motor 6 signal | PB9 | PWM14 |

Земля каждого ESC должна иметь общий потенциал с GND контроллера. Силовое
питание мотора через сигнальные контакты контроллера не проводится.

При микшере с сервоприводами PA8/PA11 становятся Servo 1/2, а моторы начинают
выделяться с PB6. Для самолётного микшера PA8/PA11 остаются Motor 1/2, а
PB6..PB9 становятся Servo 1..4. Полная карта приведена в
[разделе NAZE](pinout.md#3-naze-назначения-входов-и-выходов).

### CJMCU, встроенные коллекторные выходы

Порядок управляющих GPIO: Motor 1 PB0, Motor 2 PB9, Motor 3 PB1, Motor 4 PB8.
Прошивка задаёт частоту моторов 16 кГц и при `motor_pwm_rate > 500` использует
режим коллекторного PWM с импульсом инициализации 0. Это не карта стандартных
50/400 Гц входов внешних ESC.

## 4. Внешние I²C-устройства

### Физическое подключение

| Сигнал модуля | NAZE rev4/rev5/rev6 | CJMCU |
|---|---|---|
| SCL | PB10 / I²C2_SCL | PB6 / I²C1_SCL |
| SDA | PB11 / I²C2_SDA | PB7 / I²C1_SDA |
| GND | GND | GND |
| VCC | по схеме платы/модуля | по схеме платы/модуля |

Линии I²C требуют подтяжек. Драйвер переключает их в open-drain, но номиналы и
сам факт установки резисторов на внешнем разъёме исходниками не подтверждены.
Не устанавливайте несколько излишне сильных параллельных комплектов pull-up.

На NAZE-SP I²C в `main.c` не инициализируется, поэтому указанное подключение
внешнего I²C-модуля там программно не работает без изменения прошивки.

### Поддерживаемые драйверами адреса

| Устройство | 7-bit адрес в текущем коде | Цель |
|---|---:|---|
| MPU3050/6050/6500 | `0x68` | NAZE, CJMCU |
| ADXL345 | `0x53` | NAZE |
| MMA8451/8452 | `0x1C` | NAZE |
| BMA280 | `0x18` | NAZE |
| L3G4200D | `0x68` | NAZE |
| AK8975 | `0x0C` | NAZE |
| HMC5883L-compatible driver | `0x0D` | NAZE, CJMCU |
| BMP085/BMP180 | `0x77` | NAZE |
| BMP280 | `0x77` | NAZE |
| MS5611 | `0x77` | NAZE |
| DFRobot LED ring | `0x6D` | NAZE |

Важное замечание по текущему рабочему дереву: `drv_hmc5883l.c` использует
адрес `0x0D`, хотя соседний комментарий называет стандартный адрес HMC5883L
`0x1E`. Аналогично `drv_bmp280.c` сейчас собран для `0x77`, несмотря на верхний
комментарий про `0x76`. Таблица намеренно отражает выполняемый код, а не
типичные заводские значения датчиков. Адрес модуля должен совпасть с кодом или
драйвер нужно адаптировать.

Несколько барометров используют один адрес `0x77`, но прошивка не предполагает
их одновременную установку: она выполняет последовательное автоопределение.
MPU и L3G4200D также делят `0x68` и не должны одновременно отвечать на одной
шине.

## 5. SPI-датчик на NAZE-SP

| Модуль SPI | STM32 |
|---|---|
| CS/NSS | PB12 |
| SCK | PB13 |
| MISO | PB14 |
| MOSI | PB15 |
| GND | GND |
| VCC | по допустимому напряжению модуля |

Режим шины: SPI mode 3, MSB first. Код имеет один CS и при старте различает
M25P16 по JEDEC ID либо MPU по `WHO_AM_I`. Интерфейс не рассчитан на простое
подключение нескольких SPI-устройств с разными CS.

## 6. Ультразвуковой дальномер HC-SR04

Реально используемая `Sonar_init()` конфигурация:

| HC-SR04 | NAZE |
|---|---|
| TRIG | PB0 / RC7 / PWM7 |
| ECHO | PB1 / RC8 / PWM8 |
| GND | GND |
| VCC | 5 В согласно комментарию драйвера |

Драйвер прямо предупреждает, что PB0/PB1 — линии только 3,3 В, и предлагает
как минимум последовательный резистор 1 кОм. Один последовательный резистор не
является полноценным делителем 5→3,3 В; для надёжной защиты ECHO разумно
использовать делитель или level shifter, рассчитанный по схеме конкретной платы.

Условия прошивки: `FEATURE_SONAR` и `FEATURE_PPM`. Сонар забирает RC7/RC8 и
конфликтует с SoftSerial 2 и аналоговым RSSI/током на PB1.

В драйвере присутствует альтернативная невызванная конфигурация:

- TRIG PB8 / PWM13;
- ECHO PB9 / PWM14;
- комментарий называет эти линии 5V tolerant.

Чтобы использовать её, недостаточно только переподключить провода: нужно
изменить вызов `hcsr04_init(sonar_rc78)` на `sonar_pwm56` и пересобрать код.
При этом будут потеряны выходы OUT5/OUT6.

## 7. Светодиодное кольцо DFRobot

Кольцо использует обычную активную I²C-шину цели и адрес `0x6D`:

- NAZE: SCL PB10, SDA PB11;
- CJMCU имеет подходящую I²C1 физически, но драйвер `drv_ledring.c` не входит в
  сборку CJMCU;
- включается функцией `FEATURE_LED_RING`.

На NAZE-SP кольцо не будет работать без доработки, поскольку I²C не
инициализируется.

## 8. Телеметрия

### FrSky

Варианты порта на NAZE:

- основной UART: USART1 TX PA9 (режим 9600 бод при включении телеметрии);
- SoftSerial 1: TX PA7, RX PA6;
- SoftSerial 2: TX PB1, RX PB0.

Для однонаправленной FrSky-телеметрии используется TX выбранного порта и общая
земля. При выборе основного UART он делится с MSP/CLI: без
`telemetry_switch` телеметрия активируется при ARMED, иначе — AUX-режимом.

### Graupner HoTT

HoTT требует SoftSerial, потому что драйвер меняет направление порта RX/TX и
запрещает аппаратный UART. Соединение, заданное комментарием драйвера:

```text
HoTT DATA --------------------------> SoftSerial RX
SoftSerial TX ----[K| 1N4148 |A]---- HoTT DATA
```

Катод `K` (сторона корпуса диода с полосой) должен быть обращён к TX
контроллера, анод `A` — к общей линии HoTT. Такое включение позволяет TX
стягивать линию вниз и развязывает его, когда передаёт приёмник.
SoftSerial для HoTT не должен быть инвертирован. Сам драйвер предупреждает, что
эти GPIO не обозначены как 5V-tolerant; при 5-вольтовой линии необходима
проверка или согласование уровней.

## 9. Аналоговый датчик тока и RSSI

Доступны три значения настройки:

| CLI-значение | GPIO | Потерянная функция |
|---:|---|---|
| `1` | PA1 / ADC1_IN1 | RC2 |
| `9` | PB1 / ADC1_IN9 | RC8, SoftSerial2 TX, sonar ECHO |
| `5` | PA5 / ADC1_IN5 | внешний ADC pad rev5+ |

Для тока используется `power_adc_channel`, для аналогового RSSI —
`rssi_adc_channel`. Один канал нельзя назначить обоим измерениям. Вход должен
быть аналоговым напряжением в допустимом диапазоне STM32; PWM-RSSI напрямую
сюда не подключается без RC-фильтра, что прямо отмечено в структурах
конфигурации.

## 10. Минимальная проверка перед включением

1. Убедитесь, что выбран правильный target (`NAZE` или `CJMCU`) и ревизия платы
   действительно совместима.
2. Прозвоните GND и питание разъёма; не определяйте их по этой сигнальной
   таблице.
3. Проверьте уровни ECHO сонара, UART приёмника и телеметрии.
4. Сверьте включённые features с [матрицей конфликтов](pinout.md#9-матрица-основных-конфликтов).
5. Перед подключением винтов проверьте фактический порядок моторов через
   конфигуратор: логический `PWMx` и номер Motor — не одно и то же.
